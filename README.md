## Build Pattern

I tend to start from a concrete irritation, build the smallest real version, then tighten the system until it can survive someone else touching it.

```text
idea -> scope -> working slice -> data model -> deployment path -> tests/docs -> iteration
```

I do not mind boring reliability. I just do not like boring projects.
